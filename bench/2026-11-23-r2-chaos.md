# Chaos with the blobs in Cloudflare R2

2026-11-23, on one Mac. `scripts/chaos-r2.sh <dir> 4`: four rounds against `ludy-rivet` (release build, from the checkout) beside a `rivetdev/engine:3.1.1` container, with the server's blobs in a real R2 bucket reached through the rig's store proxy. The Mac reached the server over loopback; the server's calls to R2 crossed the internet. All 14 legs passed, and after each one the bucket held nothing.

A seed fixes the order of steps, not the drive's keys or the timing, so a seed is a label here, not a way to replay a run.

And the first loop, before this one, stopped in its fifth leg: `a_collector_cut_short_never_hands_out_what_it_marked` got no answer in 240 seconds, because the harness's way of stopping a collector after 50 deletes did them one at a time and each took a round trip to R2. What was changed for all three is in [chaos testing](../docs/evidence/chaos-testing.md#what-this-found-all-fixed). The four legs before it in that first loop had passed.

With the store gone, in these runs: an upload 503 after 0.72 s, a read after 1.3 s, a commit that has to look blobs up after 1.9 s, each with the one sentence and no address in it. With the store silent: an upload and a read 503 after 8.0 s each.

## What it left in the bucket

Nothing. The loop removed the 1884 objects it had made, by drive id, across the 14 legs. The number of requests to R2 was not counted; the proxy carried 1487 connections in the soaks alone, and each carries many requests.
